# Лига переводчиков — онлайн CRM

Закрытая CRM Лиги и личный кабинет следователя. Данные хранятся в постоянной базе Cloudflare D1. Вход и внешнее ограничение доступа обеспечивает ChatGPT Sites. Пока доступ к опубликованному сайту предоставлен только владельцу; добавление учётной записи в CRM само по себе не приглашает человека на сайт.

## Начало работы

Откройте опубликованную ссылку и войдите через тот же аккаунт ChatGPT, в котором создан проект. Отдельный пароль CRM не требуется. Добавьте заказчика в разделе «Заказчики», переводчика и его языки в «Переводчиках», затем создайте заявку.

Рабочая база первоначально пустая. Вымышленные примеры из проверок не входят в публикацию.

## Подключение следователя

1. Владелец входит в CRM. Сервер связывает рабочее пространство со стабильным идентификатором владельца; существующие записи сохраняются.
2. Создайте карточку в «Заказчиках»: ФИО, организация и телефон.
3. В разделе «Следователи» свяжите карточку с email аккаунта ChatGPT. Email и карточка фиксируются при создании; для смены email отключите старый доступ и создайте отдельный.
4. Предоставьте этому email внешнее приглашение на закрытый сайт через управление доступом Sites. Это отдельный шаг: CRM не отправляет приглашения и не расширяет аудиторию сайта.
5. Следователь открывает `/investigator` и входит через свой ChatGPT. После первого входа email привязывается к стабильной личности пользователя. Повторный вход с иной личностью с тем же email отклоняется.

В кабинете следователь указывает язык, дату и время по Москве, место и комментарий. Заявка поступает в общую CRM владельца со статусом «Новая», нулевой стоимостью и без назначенного переводчика. Администратор назначает специалиста и меняет статус. Следователь видит только обращения, отправленные из своей учётной записи; даже общая карточка заказчика не открывает ему заявки другой учётной записи.

Финансы, база переводчиков, внутренние заметки администратора и чужие обращения в кабинет не передаются. Исходный комментарий следователя хранится отдельно от внутренних заметок. Отключение доступа в CRM блокирует чтение и подачу заявок, сохраняя историю. Кабинет администратора не создаёт тестовые обращения: переход по ссылке «Посмотреть кабинет следователя» открывает предпросмотр с отключённой отправкой.

## Возможности

- Создание и редактирование заказчиков и переводчиков.
- Назначение активного переводчика с нужным языком.
- Дата и время заявки по Москве, адрес, заметки, стоимость и статусы.
- Комиссия Лиги 30%, доля переводчика 70%, полученная комиссия и задолженность.
- Поиск и фильтры, выгрузка всех заявок в CSV для Excel.
- Защита от перезаписи одновременно изменяемой записи: устаревшая правка отклоняется.
- Журнал операций в таблице `audit`.
- Кабинет следователя, связанная подача заявок, история и статусы.
- Управление доступом следователей и предпросмотр кабинета.

Суммы хранятся в целых копейках. Комиссия округляется до копейки HALF_UP. Финансовая сводка включает только выполненные заявки; задолженность равна комиссии минус сумме, которую переводчик перечислил Лиге. Оплата заказчиком и налоги в этой версии не учитываются.

Каждая операция проверяет личность и роль на сервере. Администратор определяется по секретному runtime-параметру `LIGA_ADMIN_EMAIL`, сверяемому с email из доверенных заголовков платформы, и зафиксированному идентификатору владельца. До первого входа владельца другой посетитель не может создать рабочее пространство. Следователи допускаются только по включённой учётной записи; неизвестные пользователи получают отказ. Административные API для следователя запрещены, а владельца, заказчика, статус и финансовые поля заявки задаёт сервер. Изменения требуют CSRF-токен и соответствующий Origin. SQL использует подготовленные запросы; связанные изменения и журнал выполняются атомарно. Условия назначения проверяются повторно в SQL при сохранении, а правки используют номер версии записи. Внешний доступ к сайту контролируется отдельно платформой.

## Разработка

Проект использует Vinext, Cloudflare Workers, D1 и Drizzle. Структура и инфраструктурные скрипты взяты из стартера Sites. Основная поверхность сохранена из первоначальной CRM, а сервер адаптирован для онлайн-размещения.

- `app/route.ts`: защищённая главная страница.
- `app/crm.html`, `public/app.js`, `public/style.css`: интерфейс CRM.
- `app/api/service.ts`: проверка заявок, расчёты, SQL и выгрузка.
- `app/api/access.ts`, `app/api/portal-service.ts`: роли, подключение следователей и ограниченные API кабинета.
- `app/investigator/`, `public/portal.js`, `public/portal.css`: кабинет следователя.
- `app/api/[...path]/route.ts`: получение личности от платформы и обработка API.
- `db/schema.ts`, `drizzle/`: схема и миграции базы.
- `.openai/hosting.json`: идентификатор сайта и логический D1 binding, без секретов.

Установка и сборка:

```bash
pnpm install --frozen-lockfile
pnpm build
```

В платформе Sites используйте её штатный процесс публикации. Миграции применяются при публикации, а база сохраняется между версиями. Изменённая схема требует новой миграции; уже применённые миграции не редактируются. Не публикуйте локальные базы и секреты.

Перед размещением настройте `LIGA_ADMIN_EMAIL` как секрет окружения Sites с email владельца. Значение не записывается в исходный код. Без этого параметра доступ к API закрыт. Смена владельца и перенос его идентификатора требуют отдельной миграции доступа; изменение email окружения не передаёт автоматически право на существующие записи.

## Проверки и ограничения

```bash
node --test tests/*.test.mjs
node --check public/app.js
node --check public/portal.js
./node_modules/.bin/tsc --noEmit --incremental false
```

Девять групп проверок выполняют рабочие SQL-запросы на SQLite: проверка доступа, CSRF и Origin; полный цикл заявки, округление и погашение комиссии; конфликт правок; языки и отключение переводчика; исторические расчёты; некорректные суммы и даты; выгрузка и ограничения схемы; инициализация только владельцем; передача заявок из кабинета в общую CRM; изоляция следователей; запрет административных API, подмены роли и финансов; отключение доступа; сохранение существующих данных миграциями. Адаптер тестов повторяет prepared/batch API, но не заменяет проверку реальной инфраструктуры D1. Worker проходит сборку, публикация подтверждается успешным статусом платформы.

Визуальная проверка в браузере недоступна в среде сборки. Два необязательных WebMCP-инструмента зарегистрированы для чтения данных и открытия формы заявки при поддержке браузером; выполнение в браузере не проверено. В неподдерживаемом браузере интерфейс работает без них.

Версия не включает Telegram, личные кабинеты переводчиков, оплату, генерацию договоров, проверку пересечения расписания и автоматическую рассылку приглашений. Полученную комиссию администратор указывает вручную. Журнал хранит автора, действие и время, но не предыдущие значения полей. Удаление записей отсутствует: используйте отмену заявки и отключение доступа. Следователь пока не редактирует или отменяет отправленные обращения: изменения выполняет администратор. CRM сама по себе не препятствует обмену контактами между заказчиком и переводчиком.
