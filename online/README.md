# Лига переводчиков — онлайн CRM

Закрытое рабочее пространство для заказчиков, переводчиков, заявок и комиссии Лиги. Данные хранятся в постоянной базе Cloudflare D1. Вход и ограничение доступа обеспечивает ChatGPT Sites. Новая публикация доступна только владельцу.

## Начало работы

Откройте опубликованную ссылку и войдите через тот же аккаунт ChatGPT, в котором создан проект. Отдельный пароль CRM не требуется. Добавьте заказчика в разделе «Заказчики», переводчика и его языки в «Переводчиках», затем создайте заявку.

Рабочая база первоначально пустая. Вымышленные примеры из проверок не входят в публикацию.

## Возможности

- Создание и редактирование заказчиков и переводчиков.
- Назначение активного переводчика с нужным языком.
- Дата и время заявки по Москве, адрес, заметки, стоимость и статусы.
- Комиссия Лиги 30%, доля переводчика 70%, полученная комиссия и задолженность.
- Поиск и фильтры, выгрузка всех заявок в CSV для Excel.
- Защита от перезаписи одновременно изменяемой записи: устаревшая правка отклоняется.
- Журнал операций в таблице `audit`.

Суммы хранятся в целых копейках. Комиссия округляется до копейки HALF_UP. Финансовая сводка включает только выполненные заявки; задолженность равна комиссии минус сумме, которую переводчик перечислил Лиге. Оплата заказчиком и налоги в этой версии не учитываются.

Каждая операция проверяет личность на сервере. Записи привязаны к стабильному идентификатору пользователя, который предоставляет платформа. Изменения требуют CSRF-токен и соответствующий Origin. SQL использует подготовленные запросы; связанные изменения и журнал выполняются атомарно. Условия назначения проверяются повторно в SQL при сохранении, а правки используют номер версии записи. Платформа контролирует, кто вправе открыть сайт. Если впоследствии предоставить доступ другому пользователю, он получит собственную пустую базу записей; совместное рабочее пространство сотрудников пока не реализовано.

## Разработка

Проект использует Vinext, Cloudflare Workers, D1 и Drizzle. Структура и инфраструктурные скрипты взяты из стартера Sites. Основная поверхность сохранена из первоначальной CRM, а сервер адаптирован для онлайн-размещения.

- `app/route.ts`: защищённая главная страница.
- `app/crm.html`, `public/app.js`, `public/style.css`: интерфейс CRM.
- `app/api/service.ts`: проверка заявок, расчёты, SQL и выгрузка.
- `app/api/[...path]/route.ts`: получение личности от платформы и обработка API.
- `db/schema.ts`, `drizzle/`: схема и миграции базы.
- `.openai/hosting.json`: идентификатор сайта и логический D1 binding, без секретов.

Установка и сборка:

```bash
pnpm install --frozen-lockfile
pnpm build
```

В платформе Sites используйте её штатный процесс публикации. Миграции применяются при публикации, а база сохраняется между версиями. Изменённая схема требует новой миграции; уже применённые миграции не редактируются. Не публикуйте локальные базы и секреты.

## Проверки и ограничения

```bash
node --test tests/api.test.mjs
node --check public/app.js
```

Четыре группы проверок выполняют рабочие SQL-запросы на SQLite: проверка доступа, CSRF и Origin; изоляция владельцев; полный цикл заявки, округление и погашение комиссии; конфликт правок; языки и отключение переводчика; исторические расчёты; некорректные суммы и даты; выгрузка и ограничения схемы. Адаптер тестов повторяет prepared/batch API, но не заменяет проверку реальной инфраструктуры D1. Worker проходит сборку, публикация подтверждается успешным статусом платформы.

Визуальная проверка в браузере недоступна в среде сборки. Два необязательных WebMCP-инструмента зарегистрированы для чтения данных и открытия формы заявки при поддержке браузером; выполнение в браузере не проверено. В неподдерживаемом браузере интерфейс работает без них.

Первая версия не включает Telegram, самостоятельную подачу заявки следователем, личные кабинеты переводчиков, оплату, генерацию договоров и проверку пересечения расписания. Полученную комиссию администратор указывает вручную. Журнал хранит автора, действие и время, но не предыдущие значения полей. Удаление записей отсутствует: используйте отмену заявки и отключение переводчика. CRM сама по себе не препятствует обмену контактами между заказчиком и переводчиком.
