# CRM «Лига переводчиков»

Публичный сайт: **https://liga-perevodchikov-crm.silky-globe-7217.chatgpt.site**. Следователи регистрируются и входят по номеру телефона и паролю, без ChatGPT: `/login`. В кабинете `/investigator` они отправляют заявки в общую CRM и видят только свои обращения. Финансы, база переводчиков и чужие заявки доступны администратору.

CRM владельца расположена в `/admin`. Первый вход доступен через прежний аккаунт ChatGPT; в разделе «Следователи» → «Мой вход по телефону» владелец задаёт свой номер и пароль для последующих входов без ChatGPT. При регистрации и настройке входа нужно сохранить личный код восстановления. SMS-подтверждение пока не подключено; номер является логином, а не проверкой личности.

Главная открыта для посетителей и подготовлена для Google и Яндекса: HTML, описание услуг в Волгограде, canonical, структурированные данные, robots.txt и sitemap.xml. Появление и позиции в выдаче зависят от индексации; поисковые кабинеты пока не подключены, запрос на индексацию от их имени не отправлялся. CRM, кабинеты и API защищены входом и исключены из индексации.

Исходный код онлайн-версии находится в `online/`, инструкция — в `online/README.md`. Публикация управляется через Sites; обычный GitHub-коммит сам по себе не меняет работающий сайт.

Ниже описана первоначальная локальная версия на Python 3.12+ и SQLite. Она сохранена отдельно и запускается без сторонних библиотек.

## Что работает

- Вход администратора по логину и паролю; сессии на 12 часов и выход из системы.
- Создание и редактирование заказчиков: контактное лицо, организация, телефон.
- База переводчиков: ФИО, телефон, языки, активность.
- Заявки: заказчик, язык, переводчик, дата и время по Москве, адрес, заметки, стоимость и статус.
- Назначение активных переводчиков с нужным языком. Переводчика с активными заявками нельзя отключить или удалить из его карточки нужный язык.
- Статусы: новая → назначена → в работе → выполнена; также отменена. Администратор может корректировать статус, соблюдая проверку назначения и расчётов.
- Комиссия Лиги 30%, доля переводчика 70%, полученная комиссия и остаток долга. Деньги хранятся в целых копейках; комиссия округляется до копейки по правилу HALF_UP. Итоги включают только выполненные заявки.
- Поиск, фильтр статусов и выгрузка всех заявок в CSV для Excel.
- Запись операций изменения в таблицу `audit` (в интерфейсе журнал пока не отображается).
- Сохранение данных и сессий после перезапуска.

## Локальный запуск

Скачайте репозиторий. Откройте терминал в его папке и выполните:

```bash
python app.py init-admin
python app.py serve
```

При первой команде задайте пароль минимум из 12 символов. Пароль вводится скрыто и в код не записывается. Логин по умолчанию: `admin`. Откройте **http://127.0.0.1:8000** и войдите. База при первом запуске пустая: сначала добавьте заказчика и переводчика, затем заявку.

Для другого логина используйте `python app.py init-admin --username ваше_имя`. Повторная команда для существующего логина меняет пароль и завершает его текущие сессии.

При желании загрузить вымышленные примеры в пустую базу:

```bash
python app.py seed-demo
```

Пример расчёта: услуга 8 000 ₽ → комиссия Лиги 2 400 ₽ → переводчику 5 600 ₽. При полученной комиссии 1 000 ₽ долг составит 1 400 ₽. Комиссия и долг попадут в сводку, когда заявка выполнена. Это управленческий учёт комиссии, а не учёт оплаты заказчиком, налогов и бухгалтерской выручки.

## Данные и доступ

База по умолчанию расположена в `data/liga.sqlite3`. Папка `data/`, локальные секреты и файлы баз исключены из Git. В репозитории нет настоящих заказчиков, переводчиков и паролей; примеры из `seed-demo` вымышленные. Публичность репозитория не определяет права доступа к запущенной CRM.

Можно указать отдельную базу:

```bash
python app.py --db /полный/путь/liga.sqlite3 init-admin
python app.py --db /полный/путь/liga.sqlite3 serve
```

Также поддерживается переменная окружения `LIGA_DB`.

Пароли защищены scrypt с индивидуальной солью. Сервер хранит хеши токенов сессий; cookie имеет `HttpOnly` и `SameSite=Strict`. Изменение данных требует CSRF-токен. Вход ограничен десятью попытками с одного адреса за 15 минут. Смена пароля аннулирует существующие сессии. SQL использует параметры; интерфейс экранирует текст; CSV защищает текстовые поля от формул.

## Размещение на сервере

Этот раздел относится к самостоятельному размещению локальной Python-версии. Уже опубликованная онлайн-версия использует другой сервер и платформенный вход ChatGPT. Встроенный HTTP-сервер Python предназначен для локального использования и не является готовой инфраструктурой публичного сервиса.

Для удалённого использования настройте HTTPS на обратном прокси, закрытый доступ к серверу (например, VPN), ограничение запросов на прокси и резервное копирование SQLite. Запускайте приложение от отдельного пользователя, за прокси на `127.0.0.1`, с флагом `--secure-cookie`. В этом режиме браузер получает cookie только по HTTPS. Прокси должен передавать исходный `Host`; не доверяйте произвольным forwarded-заголовкам. Ограничитель входа видит адрес непосредственного соединения, поэтому за прокси его лимит общий; настройте дополнительное ограничение по клиентскому IP на самом прокси.

Для консистентной резервной копии используйте SQLite backup API либо остановите приложение и скопируйте базу вместе с WAL-файлами. Пример онлайн-копии:

```bash
python -c "import sqlite3; src=sqlite3.connect('data/liga.sqlite3'); dst=sqlite3.connect('liga-backup.sqlite3'); src.backup(dst); dst.close(); src.close()"
```

Копия содержит рабочие данные. Храните её отдельно от Git с ограниченным доступом.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Пять интеграционных проверок проходят: полный цикл заявки, расчёт и погашение комиссии, сохранение данных после перезапуска, проверка языков и активности, некорректные суммы, вход, CSRF, выход, смена пароля, ограничение входа и CSV. Синтаксис JavaScript проверен через `node --check static/app.js`. Автоматическая визуальная проверка в браузере не выполнена: в среде сборки отсутствует браузер, а загрузка Chromium недоступна. Перед рабочим использованием проверьте формы и мобильную вёрстку в своём браузере.

## Границы первой версии

Сейчас реализован внутренний интерфейс администратора. Личные кабинеты следователя и переводчика, самостоятельная подача заявки, Telegram, документы и онлайн-оплата ещё не подключены. CRM сама по себе не препятствует обмену контактами между заказчиком и переводчиком.

Временная доступность переводчика по расписанию и пересечения заявок пока не проверяются. Статус «активен» означает возможность назначать заявки, а не подтверждённую доступность в конкретный час. Полученную комиссию администратор указывает вручную; банковские платежи не проверяются. Операции удаления отсутствуют: используйте отмену заявки или отключение переводчика. Журнал операций фиксирует автора и время, но не хранит предыдущую версию полей. Ролевая модель, восстановление пароля по почте и второй фактор не реализованы.
